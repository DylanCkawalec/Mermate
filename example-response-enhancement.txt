PCVC (PCVC Data Enrichment Virtual Machine Whitepaper V1; Mentibus / PCVC Architecture Draft) is a proprietary data enrichment virtual machine, API, and graph protocol that converts public and permitted business signals into high-trust, provenance-rich records for People, Companies, and Venture Capital firms (VCs) by treating every candidate datum as a source-cited claim (W3C PROV principles) rather than truth, and by exporting only schema-valid Mentibus-ready CSV/XLSX/JSON projections from a canonical temporal relationship graph.

Actors/personas: Mentibus / Operator, Mentibus operator, Data engineer, Analyst, Reviewer, Administrator, Model engineer.

The system accepts input jobs (\mathcal{I}) for Person, Company, VC, Event, Round, and Campaign targets and produces outputs (\mathcal{O}) including JSON, CSV, XLSX, provenance manifests, rejected rows, Mentibus submission artifacts, observability/audit reports, and post-training datasets. Operational targets are 3,000 valid People/day and 500 valid Companies/day, plus campaigns that extract 100–300 high-value new People/Companies/VCs from events, funding rounds, investor announcements, and news coverage. Quality objective: maximum useful enrichment under accuracy/provenance/recency/privacy/source permission/Mentibus schema constraints.

System doctrine/laws:
- No source, no fact.
- No provenance, no export.
- AI is an extractor and assessor, not an oracle.
- A profile is a claim bundle.
- The graph is the product (CSV is interface).
- Lifecycle is probabilistic and must be stored as assessments not facts.
- People data is narrower than company data (purpose limitation, data minimization; avoid private addresses/phones/sensitive traits/family/precise private location; GDPR Art. 5 as design reference).
- PCVC is explicitly not a private-person surveillance system, not password-bypassing scraping, not unauthorized profile copying, not generative text treated as fact, and not raw spreadsheet generation without lineage.

Primary entity set E={Person, Company, VC, Fund, Event, Round, Product, Article, Source, Claim}.
Relationship set R={works_at, founded, partner_at, invested_in, led_round, raised, sponsored, spoke_at, portfolio_of, announced, launched}. Graph edge types also include Product launched_by Company and Article mentions Entity.

Claim \kappa=(s,p,o,u,e,t_r,t_x,m,c) contains subject/predicate/object, source URL u, evidence span e, retrieval time t_r, extraction time t_x, extractor metadata m, confidence c.
Exports are defined as CSV=\pi_schema(Profile(E)); CSV is not source of truth.

Job state machine:
Created -> SourceDiscovery -> SourcePolicyCheck -> Fetching -> Parsing -> ClaimExtraction -> ClaimNormalization -> EntityResolution -> GraphWrite -> ConfidenceScoring -> LifecycleAssessment -> ConflictDetection -> PrivacyFilter -> SchemaValidation -> ExportReady -> Submitted.
First-class failure states:
- Quarantined
- PolicyBlocked
- InsufficientEvidence
- ConflictRequiresReview
- SchemaInvalid
- FetchFailed
- ExtractorFailed
- ResolverFailed
- SubmitFailed

Failure handling by stage:
- Job Router failure: invalid target type, malformed constraints, or unsupported export mode routes job to Quarantined or SchemaInvalid before external work begins.
- Source Discovery failure: no policy-eligible URLs or no sufficiently ranked candidates leads to InsufficientEvidence with discovery trace retained.
- Source Policy Gate failure: blocked/restricted/unlicensed sources produce PolicyBlocked with stored decision record and no fetch execution.
- Crawl/Fetch/Cache failure: DNS/TLS/HTTP/robots/timeouts/rate-limit exhaustion/content corruption produce FetchFailed; partial fetches remain cached only if policy allows retention.
- Structured Parsing failure: malformed HTML/PDF/table parse errors continue to fallback extractors where allowed; if no extractor succeeds, ExtractorFailed.
- AI Claim Extraction failure: schema-invalid output, unsupported claims, prompt injection detection, model timeout, or no evidence-backed claim produce ExtractorFailed or InsufficientEvidence depending on whether extraction was technically successful but yielded nothing usable.
- Claim Normalization failure: invalid URL/domain/date/currency normalization does not create facts; affected claims remain flagged and can route to ConflictRequiresReview or Quarantined if required fields become impossible.
- Entity Resolution failure: candidate retrieval failure or ambiguous merges in review band route to ResolverFailed or ConflictRequiresReview; no destructive merge occurs without threshold satisfaction.
- Relationship Graph Write failure: graph transaction failure, version conflict, or snapshot write failure prevents downstream export and leaves job resumable from last durable checkpoint.
- Confidence and Trust Scoring failure: missing feature inputs or scoring pipeline error routes to Quarantined; stale but valid upstream claims remain stored.
- Lifecycle Prediction failure: lifecycle output is omitted or stored as unknown if prediction cannot be computed; lifecycle must never block non-lifecycle exports unless include_lifecycle is required by job constraints.
- Conflict Detection failure: unresolved contradictions on critical fields route to ConflictRequiresReview unless confidence gap exceeds configured threshold.
- Privacy and Purpose Filter failure: sensitive personal data, unsupported People fields, or purpose violations route to Quarantined with privacy event log.
- Schema Validation failure: invalid Mentibus row format or missing required fields routes to SchemaInvalid and writes rejected row artifacts with reasons.
- Mentibus Submission failure: transport/API/schema rejection after package build routes to SubmitFailed; export package and audit trail are retained for replay.
- Post-Training Artifact Generation failure: should not retroactively invalidate already exported package; artifact generation errors are logged in observability/audit reports and retried asynchronously.

Source governance/crawl protocol:
- classify sources as Official primary, Licensed API, High-trust media, Structured public web, User-supplied data, Restricted platforms, Low-trust mirrors, Sensitive sources
- treat robots rules per RFC 9309 as input not authorization
- enforce explicit LinkedIn boundary: validate/use LinkedIn URLs only if user-supplied/licensed/lawfully obtained; do not implement unauthorized automated scraping (LinkedIn User Agreement reference)

Source priority scoring before fetch:
Priority(u)=0.24Rel(u)+0.20Auth(u)+0.18Novelty(u)+0.16Fresh(u)+0.12Extractability(u)-0.10Risk(u)
Stored crawl decision record contains url, canonical_url, domain, source_class, robots_status, terms_status, policy_status, crawl_priority, retrieved_at, http_status, content_hash.

Extraction architecture:
prefer deterministic structure before generative, in this order:
JSON-LD -> Schema.org microdata/RDFa -> Open Graph/metadata tags -> HTML tables/lists -> DOM text blocks -> PDF/attachments -> AI-assisted claim extraction -> search snippet fallback as weak evidence.
Extractor contract emits common claim envelope with candidate_claim_id, subject_text/type, predicate, object_text/type, evidence_text, source_url, extractor, model_version, raw_confidence.
AI extraction prompt contract:
- extract business enrichment claims only from supplied source text
- do not infer private personal information
- do not invent values
- every claim must include subject/predicate/object/evidence_text/source_url/confidence
- return no claim if insufficient evidence
- mark lifecycle/behavior outputs as assessment_not_fact=true

Entity resolution:
- conservative typed similarity
- Person similarity Sim(P_i,P_j)=0.30U+0.25N+0.18C+0.12T+0.10E+0.05G with merge if Sim>=0.92 and review band 0.78<=Sim<0.92
- Company resolution primarily uses normalized domain with CompanyID=hash(normalized_domain) and routes domain conflicts to review
- VC resolution uses firm domain, fund names, portfolio page, partner names, round behavior and separates Firm, Fund, Partner, Round entities
- stores resolution explanation for merge/review/create decisions
- %% [enhanced] Resolver writes no irreversible merge when evidence falls inside the review band; ambiguity is retained as conflict material rather than collapsed identity.

Relationship graph:

Relationship weight W(r)=Conf(r)×Recency(r)×Specificity(r)×SourceAuthority(r).
Store both specific and weak semantics, but weight downstream.
The graph is temporal, versioned, and snapshot-capable so that exports can be reproduced from the same source snapshots/schemas/model versions.

Confidence/trust math:
Claim confidence Conf(\kappa)=\sigma(0.25A_s+0.20Q_e+0.20C_i+0.15F_r+0.10M_a+0.10S_t-0.35X_c)
where A_s source authority, Q_e evidence span quality, C_i independent corroboration, F_r freshness, M_a model agreement across extractors, S_t structured extraction confidence, X_c contradiction penalty.
Source authority Authority(s)=0.35Primary(s)+0.20DomainTrust(s)+0.15Structured(s)+0.15Fresh(s)+0.15History(s).
Freshness decay Conf_t(\kappa)=Conf_0(\kappa)e^{-\lambda\Delta t} with predicate-dependent decay.
Profile trust Trust(entity)=0.30Completeness+0.25Evidence+0.20Consistency+0.15Freshness+0.10SourceDiversity.
Export gates:
- Trust>=0.85 auto-export if schema/policy pass
- 0.65–0.85 review or low-confidence staging
- <0.65 quarantine

Lifecycle prediction:
Lifecycle is probabilistic assessment and must not be written as direct fact unless source explicitly states.
Company lifecycle states {ideation, pre_seed, seed, launch, early_revenue, growth, scale, mature, pivot_or_decline, unknown} with features {funding_stage, funding_recency, hiring_velocity, event_presence, media_frequency, product_launch_signals, partnership_signals, customer_signals, founder_activity, investor_quality} and model Lifecycle(C)=softmax(Wx_C+b) producing distribution plus evidence_claim_ids, confidence, assessment_not_fact=true.
Person lifecycle states {operator, founder, executive, investor, advisor, board_member, speaker_thought_leader, career_transition, unknown} with caution not to infer sensitive personal attributes.
VC lifecycle/behavior states {emerging_manager, active_seed_investor, active_growth_investor, sector_specialist, generalist, follow_on_heavy, portfolio_support_heavy, quiet_or_inactive, unknown} predicted from round recency/count, sector concentration, co-investor centrality, partner event activity, portfolio updates, follow-on behavior.

Correlation analytics:
answer core questions about events yielding high-trust People, event correlation with future funding, VC sector activity shifts, company transitions after product/event signals, people movement operator->founder/founder->investor, co-investor clusters, media sources with highest verified yield, consistently missing fields.
Temporal correlation Corr_h(X,Y)=corr(X_t,Y_{t+h}) with examples:
- sponsorship->funding +180d
- hiring velocity->lifecycle transition +90d
- VC centrality->portfolio growth +365d
Explicit note: correlation not causation.
Graph correlation model uses adjacency A_t, features F_t, labels L_t with P(L_{t+h}|A_t,F_t)=g_\theta(A_t,F_t).

Algorithms:
Source Discovery builds query templates, searches approved providers, expands permitted links, classifies source type, canonicalizes/dedupes, scores priority, sends to policy gate.
Extraction parses structured first, extracts tables/lists/metadata/DOM/PDF, chunks into evidence spans, calls AI only on relevant spans, validates output schema, normalizes fields, stores candidate claims.
Entity Resolution retrieves candidates by URL/domain/name/embedding, computes typed similarity, merges/reviews/creates new, stores resolution explanation.
Export collects required fields, selects canonical claims by confidence/recency, checks conflicts, checks privacy/source policy, computes trust, validates schema, writes row or rejection.
